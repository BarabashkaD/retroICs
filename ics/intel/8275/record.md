| CRT-1 | Reset command (00h) and power-up | Command 0000 0000 (A0 = 1), then 4 parameters (A0 = 0): byte 1 `S HHHHHHH`, byte 2 `VV RRRRRR`, byte 3 `UUUU LLLL`, byte 4 `M F CC ZZZZ`. Action: "DMA requests stop, 8275 interrupts are disabled, and the VSP output is used to blank the screen. HRTC and VRTC continue to run. HRTC and VRTC timing are random on power-up. As parameters are written, the screen composition is defined." IE and VE are reset by Reset (status flag text); IRQ goes inactive on Reset ("not recommended during normal service"). Power-up: "the 8275 Interrupt Enable Flag may be set", so the cold start must write a Reset before system interrupts are enabled. No reset pin (CRT-40). No other power-up value is given. Values of IE, VE, IRQ: "Timing (data sheet)", Reset row | [D79] 1-178 (PDF 17), 1-172 (PDF 11) Note, 1-180 (PDF 19); [D84] 8-66, 8-60; [D8275K] 8-233 |
| CRT-2 | Character counter, HHHHHHH, ZZZZ, HRTC | H = characters per row - 1: 0000000 = 1 ... 1001111 = 80; 1010000..1111111 "Undefined". ZZZZ = character counts per HRTC: 0000 = 2, 0001 = 4, 0010 = 6 ... 1111 = 32, i.e. 2 (Z + 1). Counter: counts the display characters (1-80), "then causes the line counter to increment, and it starts counting out the horizontal retrace interval (programmable from 2 to 32). This is constantly repeated." HRTC edges: "Timing (data sheet)" (HRTC row). During HRTC VSP is high and LTEN low (pin 7) | [D79] 1-178 (PDF 17), 1-171 Fig. 15 (PDF 10), 1-163 (PDF 2); [D84] 8-66, 8-70 Line Timing |
| CRT-3 | Row counter, RRRRRR, VV, VRTC | R = rows per frame - 1: 000000 = 1 ... 111111 = 64. VV = row counts per VRTC - 1: 00 = 1, 01 = 2, 10 = 3, 11 = 4. "The row counter is an internal counter driven by the line counter. It controls the functions of the row buffers and counts the number of character rows displayed." "After the row counter counts all of the rows in a frame (programmable from 1 to 64), it starts counting out the vertical retrace interval (programmable from 1 to 4)." Fig. 17: VRTC high from the first to the last retrace row. VRTC edges: "Timing (data sheet)" (VRTC row). During VRTC VSP is high and LTEN low (pin 8) | [D79] 1-178, 1-171 Fig. 16, 17 (PDF 10), 1-183 Fig. 27, 28; [D84] 8-66, 8-71 |
| CRT-4 | Line counter, LLLL, M, LC0-3 | LLLL = lines per row - 1: 0000 = 1 ... 1111 = 16 (the 1-178 table; the 1-169 text "programmable from 1 to 16"). "The 8275 is designed to hold the line count stable while outputting the appropriate character codes during each horizontal sweep. The line count is incremented during horizontal retrace and the whole row of character codes are output again during the next sweep." M = 0: LC = line number; M = 1: LC = line number - 1, and "while the first line (line number 0) is being displayed, the last count is output". Fig. 10 (16 lines): mode 1 gives 1111, 0000, 0001 ... 1110; Fig. 11 (10 lines): mode 1 gives 1001, 0000 ... 1000. Mode 0 suits ROMs that "leave address zero blank and start at address 1", mode 1 ROMs "which start at address zero". LC change at the HRTC rise: "Timing (data sheet)" (line and row counters row) | [D79] 1-169 Fig. 10, 11 (PDF 8), 1-178 (PDF 17), 1-171 Fig. 15 |
| CRT-5 | Underline line UUUU, top / bottom blanking | "Underline placement is also programmable (from line number 0 to 15). This is independent of the line counter mode." Line number of the underline > 7 (MSB = 1): "the top and bottom lines will be blanked" (VSP); ≤ 7: not blanked (note on 1-178: "uuuu MSB determines blanking of top and bottom lines (1 = blanked, 0 = not blanked)"). "If the line number of the underline is greater than the maximum number of lines, the underline will not appear." Underline is made by LTEN, blanking by VSP. Fig. 12: 12-line row, underline in line 10, lines 0 and 11 blanked. Fig. 13: 8-line row, underline in line 7, not blanked. The 1-178 parameter table numbers the underline lines 0000 = "1" ... 1111 = "16", the same style as the LLLL table (0000 = 1 line): read as the first .. sixteenth line, i.e. line number = UUUU, which is the only reading that agrees with "line number 0 to 15", "MSB = 1" and the pin text "number 8 or greater" (pin 35). The same table in [D84] 8-66 | [D79] 1-170 Fig. 12, 13 (PDF 9), 1-178 (PDF 17), 1-163 pin 35 (PDF 2); [D84] 8-66 |
| CRT-6 | Spaced rows (S) | S = 0 normal rows, 1 spaced rows. "The 8275 can also be programmed to blank alternate rows. In this mode, the first row is displayed, the second blanked, the third displayed, etc. DMA is not requested for the blanked rows." Fig. 9 draws rows 1 ... 64, each separated by an unnumbered blank row. Whether RRRRRR counts the blanked rows: SILENT | [D79] 1-169 Fig. 9 (PDF 8), 1-178 |
| CRT-7 | Start Display (001SSSBB), Stop Display (40h) | Start Display `0 0 1 S S S B B`, no parameters: "8275 interrupts are enabled, DMA requests begin, video is enabled, Interrupt Enable and Video Enable status flags are set" (SSS, BB: CRT-21). ### Decisions

- S11 / S12 order (decided 2026-11-10, D11): an underrun pending at Preset Counters does not suppress the row-0 fill of the resume; the preset clears the underrun's DMA stop, the underrun blanking stays until the row-0 start. [D79] 1-179 / 1-180 do not give the order; a real system decides: the board of [R86] with the monitor [MON] shows an aligned picture after every tape operation, which always leaves an underrun. (Since 2026-11-11 every underrun's DMA stop ends at the start of the last retrace row, next item, so the resume ends it with no clear of the preset's own; the outcome of this ruling is unchanged.)
- S11 / CRT-25 underrun restart (decided 2026-11-11, D11; approved for now by the maintainer 2026-11-11, to be checked on a real 8275 with a logic analyser: "Hardware checks" below; supersedes the reading "DMA stopped through the whole vertical retrace, the row-0 fill skipped", used to 2026-11-10): after an underrun the DMA stop ends at the start of the last retrace row, so the row-0 fill of the next frame happens as in every frame; the underrun blanking stays until the row-0 start; DU set and cleared, the rest of the frame blanked and without DMA, as before. [D79] 1-180 "until after the vertical retrace interval" does not say whether the row-0 fill belongs to it; on the board of [R86] and [K14] with the monitor [MON] the picture is aligned after boot whatever the phase of Start Display (the monitor sends it before it enables the 8257), and the old reading left the picture one row out of step with the 8257 block (a simulation of that board, 2026-11-11). Rule: a reading that leaves the picture one row out of step contradicts that evidence and is not taken.
- CRT-21 burst space reference point (2026-11-10): [D79] 1-172 Fig. 18 draws the burst space from the DRQ fall (the last WR↓ of the burst), while the model's checks measure it from the last WR↑. With the real 8257 (WR about 0.75 CCLK) both readings fall inside the drawn range; with a test stand-in that holds WR for about 1.9 CCLK, the Fig. 18 reading would be about 8.9 CCLK for SSS = 001, outside '7 ±1'. The WR↑ reference is kept for the checks.
- CRT-25 DU set moment (2026-11-10): tb_vg75_dma shows DU persistence until a status read ([D79] 1-180), so the first DU read after the underrun comes one line after the row 8 start; the set moment is therefore bracketed (3 CCLK before the row 6 start .. one line after the row 8 start), not pinned. The blanking from the row 6 start is pinned at the pins (VSP); the model sets DU in the same statement as the blank. Pinning both would need a second underrun in a later frame.
- CRT-33 / CRT-34 cursor and VSP (2026-11-10): pin 35 ([D79] 1-163) lists VSP "at regular intervals (1/16 frame frequency for cursor, ...) to create blinking displays"; the cursor text ([D79] 1-177, [D84] the same) gives only the formats and the rate. Taken (the maintainer's choice, 2026-11-10): the cursor blinks through RVV / LTEN only, the character under it stays visible; VSP at a blinking cursor cell is unchecked. Open: decide from a primary source (a data sheet text, or the screen of a real system with an 8275: the [R86] text, a photo or a video).

Preset Counters in other models (comparison only):

- [MAME]: E0h stops the scanline and HRTC timers (i8275.cpp:626-634); the next command of any kind sets the scanline to the start of the last retrace row (`m_vrtc_drq_scanline`) and restarts them (540-557). Its TODO list (line 30) leaves the effect on DMA and HRTC open.
- [EMU]: E0h presets the counters and stops the raster with HRTC and VRTC inactive (Crt8275.cpp:430-435, 725-733); every other command restarts it (`startRasterIfNotStarted`, 384-428, 660-666) at display row 0, line 0 (737-748).

Decision: in the data sheet reading the counters stop at E0h until the next command. [MAME] and [EMU] hold the counters in the same way, so the data sheet behaviour is taken. The restart position is only "top left corner" in the data sheet. Taken (D11, 2026-11-10): the top left corner of the frame cycle, whose first DMA fills the row 0 buffer during the last retrace row, because a real system ([R86], [MON]) keeps the picture aligned after tape I/O (reason below); [MAME] restarts at the same point, which is a comparison only, not the reason. [EMU]'s row 0 restart works in Emu80 because its CRT fetches a row during that row (Crt8275.cpp:516-546, 611-633), not a row ahead.
